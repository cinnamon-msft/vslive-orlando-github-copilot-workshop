You've made a change to the space quiz and added project instructions. Now you'll use a more deliberate process for another improvement: start from an issue, plan the work, let Copilot implement it with **Autopilot**, and verify the result with a reusable skill.

In this lesson, you will:

- start a fresh session from an open space quiz issue.
- use **Plan** mode to plan the feature, then **Autopilot** to build it.
- confirm the generated code follows the instructions you merged earlier.
- create and use a `quality-checks` skill that fits this project.

## Scenario

Choose another small, open space quiz issue from the repository. If the guided tour backlog is empty, create an issue for a focused improvement, such as a question category selector or a restart button. Keep the issue's acceptance criteria clear enough to plan and verify in one session.

## Background

Introducing AI coding agents to your development flow doesn't change the fundamentals. If anything, they become even more important! Most developers follow a flow that resembles:

1. Open a filed issue with details of what needs to be done.
2. Create a plan of what needs to be built.
3. Build and review the code.
4. Run checks and validate the behavior.
5. Create a pull request.
6. Once the code has been reviewed and the required checks succeed, merge the code.

By sticking to this standard approach you ensure the code generated by AI meets the requirements set forth, and goes through the same vetting process as code written by hand.

## Session modes

The **session mode** controls how much autonomy the agent has. You can set it from the dropdown below the prompt field and change it at any time:

- **Interactive**: You and the agent work together. The agent suggests changes and waits for your input before proceeding.
- **Plan**: The agent creates a plan first. You review and approve the plan before the agent executes it.
- **Autopilot**: The agent works autonomously—writing code, running available checks, and iterating without waiting for input.

## Plan the feature

1. In **My work**, open the issue you selected and choose **New session**.
2. Select <kbd>Shift</kbd>+<kbd>Tab</kbd> until the mode displays **Plan**.
3. Send this prompt. The issue is already in the session's context:

   ```plaintext
   Plan the work based on the requirements in this issue. Follow .github/copilot-instructions.md, keep the project as a single dependency-free index.html, and explain how you will verify each acceptance criterion. Ask any clarifying questions you need before implementation.
   ```

4. Answer any follow-up questions based on how you'd build the feature.
5. Review the plan. It should include the relevant changes to the quiz and a concrete way to verify the issue's acceptance criteria. Refine the plan before approving it if needed.

## Build it with Autopilot

1. In the plan summary, select the option closest to **Approve and implement with autopilot**.
2. Let the agent implement the plan and run any relevant checks.
3. If the agent moves beyond the agreed scope or adds dependencies without a clear need, stop it and ask it to follow the plan and repository instructions.

## Review the changes

1. Select **Changes** in the upper right to open the code changes.
2. Review the diff. Confirm the agent followed the project instructions, kept the implementation focused, and preserved existing quiz behavior.
3. Open the quiz in the integrated browser and manually check the issue's acceptance criteria. Also check keyboard interaction and any relevant light or dark theme states.
4. If anything is missing, ask Copilot to fix it, then review and test the updated change.

## Create a quality-checks skill

The repository is a single HTML file without a package manifest or a built-in test suite, so its verification process should be explicit and honest about what is and isn't automated. An **agent skill** packages repeatable guidance that Copilot can load when a task matches its description.

1. In the review panel, open the repository's file view and inspect `.github/skills`. If the folder does not exist, ask Copilot to create it.
2. Ask the agent to create `.github/skills/quality-checks/SKILL.md` with a clear `name` and `description`.
3. Have the skill explain how to review the diff, check that `index.html` remains dependency-free, validate relevant HTML/JavaScript behavior in the integrated browser, and report checks accurately. It should not claim a test suite or lint command exists unless the project has one.
4. Review the skill instructions to ensure they are useful for future changes and don't claim that checks ran when they didn't.
5. Ask the agent to use the skill to verify this feature. For example, enter `/quality-checks` if the skill is available as a slash command; otherwise ask it to run the quality-checks skill by name.
6. Review the report and resolve any issues it finds.

Skills are loaded dynamically. The skill's `description` should explain when it applies so the agent can select it appropriately.

## Keep the session open

Don't create a pull request yet. In the next lesson you'll add the Playwright MCP server and ask the agent to explore this feature in a real browser. Keep this session open.

You used a complete issue-to-implementation workflow and created a reusable validation skill. Specifically, you:

- checked that the generated code followed the repository instructions.
- reviewed the diff and manually verified the feature in the integrated browser.
- created and used a skill that reflects the project's actual verification options.
